# 사진 모으기 체크리스트

중고나라에서 평가용 사진을 모을 때 이 순서대로 한다. 숫자를 믿을 수 있으려면
**좋은 결과가 나올 것 같은 사진을 고르지 않는 것**이 제일 중요하다 (고르면 통과율이 부푼다).

설계 근거: `study/2026-09-29-test-cleanup.md` §4 — test 100장이면 통과율 95% 구간이 ±8%p,
50장이면 ±11%p, 경로별로 나누면 그 두 배 가까이 벌어진다.

## 1. 규칙 (모으기 전에 읽기)

1. **검색어는 아래 표에서만** 고른다. 표에 없는 걸 찾고 싶으면 먼저 표에 적고 쓴다
2. 검색 결과를 **최신순**으로 보고, 조건에 맞는 **첫 게시글의 첫 사진**만 가져온다
   - 첫 사진이 제외 기준에 걸리면 그 게시글은 건너뛰고 다음 게시글 (같은 글의 두 번째 사진으로 바꾸지 않는다)
   - "이건 결과가 안 좋겠다" · "이건 잘 되겠다"는 이유로 건너뛰지 않는다
3. 한 검색어에서 **최대 3장** — 한 종류 물건이 몰리지 않게. 채우면 다음 검색어로
4. 층 목표를 다 채우면 그 층은 멈춘다 (`python eval/intake.py status` 로 확인 — 넘기면 `add` 가 거부한다)
5. 같은 판매자 사진은 한 장만

**제외** (이런 첫 사진은 건너뛴다)

- 사람이 주인공 (착용샷, 얼굴이 크게 나옴)
- 스크린샷 · 캡처 · 쇼핑몰 공식 이미지 (판매자가 직접 찍은 사진이 아님)
- 여러 장을 한 장으로 합친 콜라주
- 물건이 너무 작거나 안 보임 (물건이 사진의 1/10 도 안 됨)
- 가격표 · 글만 있는 이미지

**제외하지 않는 것** — 흔들림 · 어두움 · 지저분한 배경 · 워터마크 · 비스듬한 각도.
이게 실제 사용자가 올리는 사진이다.

## 2. 층별 목표와 검색어

`코드`는 파일 이름 앞에 붙인다. 층은 **사진을 보고** 정한다 (검색어가 "하자"여도 사진이 멀쩡하면 none).

| 코드 | 층 | test | dev | 어떤 사진 | 검색어 |
|---|---|---|---|---|---|
| `none` | 물건 · 하자 없음 | 25 | 5 | 새것 같은 물건 | 무선이어폰, 운동화, 백팩, 텀블러, 키보드, 스탠드 조명, 전기포트, 게임패드, 선글라스, 손목시계 |
| `light` | 물건 · 작은 하자 | 25 | 5 | 얼룩 하나 · 긁힘 몇 개 · 사용감 | 위 검색어 + "사용감", "생활기스", "스크래치" |
| `heavy` | 물건 · 큰 하자 | 10 | 3 | 녹 · 도장 벗겨짐 · 찢김 · 흠집이 넓게 | 하자 있음, 고장, 부품용, 녹, 도색 벗겨짐, 가죽 까짐 |
| `dense` | 물건 · 잔글씨 많음 | 10 | 3 | 라벨 · 성분표 · 눈금 · 스펙 표가 크게 보임 | 화장품, 영양제, 공구, 전자제품 박스, 향수, 계측기 |
| `doc` | 글자가 곧 물건 | 15 | 4 | 표지 · 제목이 물건의 전부 | 전공책, 소설, 문제집, 만화책, CD 앨범, LP, 악보 |
| `inside` | 물건 일부 · 내부 | 8 | 2 | 엔진룸 · 뜯은 기기 · 한 곳 클로즈업 | 엔진룸, 메인보드, 그래픽카드, 노트북 분해, 시계 무브먼트, 자동차 실내 |
| `edge` | 경계 사례 | 7 | 3 | 분류가 애매하거나 오리기가 어려운 것 | 포토카드, 앨범 구성품, 보드게임, 유리컵, 크롬 도금, 투명 케이스 |
| | **합계** | **100** | **25** | | |

- dev 는 조정용 — 실패를 보고 프롬프트를 고쳐도 된다. test 는 동결 — 결과만 본다
- test/dev 는 정리 스크립트가 층별로 나눈다 (직접 고르지 않는다)
- test/dev 는 층마다 자리를 미리 섞어 두고 들어온 순서대로 채운다 — 조금씩 `add` 해도 dev 가 한 검색어에 몰리지 않는다
- 한 번 정한 split 은 `splits.jsonl` 에 남는다. `status` 가 바뀐 게 있으면 알려 준다
- 기존 8장(`phone_img/` 에서 온 사진)은 규칙 없이 고른 사진이라 **층 목표에 세지 않고** dev 에 따로 둔다
- 규칙 전에 모았거나 결과를 먼저 볼 사진(파일럿)은 `add --pilot` — 역시 층 목표 밖, 전부 dev

## 3. 저장

1. 사진을 `backend/eval/images/inbox/` 에 저장한다. 파일 이름: `<코드>_<아무거나>.<확장자>` (jpg · png · webp 만 —
   heic · gif 는 다시 저장. 섞여 있으면 `add` 가 거부한다)
   - 예: `none_airpods.jpg`, `doc_linear_algebra.webp`, `heavy_03.png`
   - 네이버 카페 이미지는 우클릭 → 이미지 저장 (주소로 내려받으면 막힐 때가 많다)
2. 게시글 주소를 `images/inbox/urls.txt` 에 한 줄씩: `파일이름 주소` (마지막 칸이 주소 — 이름에 공백이 있어도 된다)

   ```text
   none_airpods.jpg https://cafe.naver.com/joonggonara/123456789
   doc_linear_algebra.webp https://cafe.naver.com/joonggonara/123456790
   ```

3. 모인 만큼 정리한다 (중간중간 해도 된다)

   ```bash
   cd backend
   python eval/intake.py status          # 층별로 몇 장 모였나
   python eval/intake.py add             # inbox → images/, dataset.json 에 추가, dev/test 나눔
   ```

   `add` 가 라벨 달 항목을 `images/inbox/labels.csv` 로 뽑아 준다. 파일이 이미 있으면 **채워 둔 칸은 그대로 두고**
   새 사진 줄만 더한다 — 라벨을 반쯤 달다가 사진을 더 모아도 된다.
   하나라도 틀리면(이름 규칙 · 같은 이름 · 같은 사진 · 층 목표 넘음) 아무것도 옮기지 않는다.

## 4. 라벨 (실행하기 전에)

`labels.csv` 를 스프레드시트로 열어 채운다. 기준은 `README.md` 의 "정답 라벨" 표.
기존 8장(초안 라벨 `claude-draft`)도 들어 있다 — 확인하고 고쳐 넣으면 이름이 바뀐다.

**엑셀 주의** — 엑셀은 `1-2` 를 날짜로, `1E5` 를 숫자로 바꾸고 앞자리 0 을 지운다. `key_texts` 는 그대로여야 할
글자라 이러면 정답이 틀어진다. `merge` 가 날짜·숫자처럼 보이는 값을 경고하지만, 모델명·숫자가 있으면
**데이터 → 텍스트/CSV 에서 → 열 형식 "텍스트"** 로 불러오거나 구글 시트에서 그 열을 "일반 텍스트"로 두고 채운다.
저장은 "CSV UTF-8" 이 좋다 (일반 CSV 로 저장해도 읽기는 한다).

| 열 | 값 |
|---|---|
| `photo_type` | `document` / `inside_view` / `product` |
| `wear_level` | `none` / `light` / `heavy` |
| `text_level` | `none` / `simple` / `dense` |
| `key_texts` | 결과에서 그대로여야 할 글자 — 여러 개면 `\|` 로 구분 (예: `선형대수\|WILEY`) |
| `item` | 짧은 영어 명사 (참고용) |
| `ambiguous` | 판단이 애매하면 `y` — 나중에 따로 집계한다 (report 에는 아직 없음) |
| `note` | 자유 |

```bash
python eval/intake.py merge images/inbox/labels.csv --by <이름>
```

- 값이 하나라도 틀리면 전부 반영하지 않는다 (대소문자는 안 가린다). 빈 줄은 건너뛴다
- test 사진의 사람 라벨은 한 번 달면 바꾸지 않는다 — 결과를 보고 정답을 옮기지 않게. 정말 틀렸으면 `--relabel`
- 층(파일 이름 코드)과 라벨이 달라도 된다 — 집계는 라벨 기준이다. 층은 "모을 때의 의도"
- 20장 정도는 다른 사람도 따로 라벨을 달아 두면 라벨 자체가 흔들리는지 볼 수 있다

## 5. 걸리는 시간

사진 한 장에 저장 30초 + 주소 10초 → 125장 약 1.5시간. 라벨 한 장에 30초 → 약 1시간.
