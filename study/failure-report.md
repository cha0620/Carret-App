# 실패 레포트 (2026-09-14 ~ 10-11)

날짜별 study 노트 14개에서 **안 된 것 · 버린 방향 · 틀린 판단**만 주제별로 모았다.
각 줄 끝의 `(MM-DD §n)` 은 원 노트 위치. 숫자는 대부분 Claude 1차 관찰 + 소표본이라 "방향" 수준이다.

한 줄 요약: **생성 모델은 시킨 것보다 "보이는 단서"를 따른다** — 쓴 단어, 넣은 사진, 강조한 목록을 그린다.
그래서 이긴 방향은 늘 "덜 넣기"(최소 문장 · 선 그림 · 배경 교체)였고, 검사는 "생긴 것"보다 "사라진 것 · 바뀐 모양"을 못 봤다.

## 1. 생성이 물건을 바꾼다

| 실패 | 사례 | 원인 (추정 포함) | 지금 |
|---|---|---|---|
| 하자 · 디테일을 메움 | 디스트레스 구멍 8/8 메워짐(edge_clothes2), 주전자 찌그러짐 → 매끈, 승용차 얼룩 정돈 | 생성은 "정돈"을 기본으로 한다 | 넓은 흔적은 생성 안 함 → 판매자 선택 (10-04 §4, 10-11 §2) |
| 하자를 지어냄 | Braun 몸통에 없던 긁힘, 승용차에 원본보다 큰 녹 | "흠집을 지켜라" 목록이 오히려 그리게 함 | 하자 앵커 삭제 (09-27 §5 · §9) |
| 소재 · 색 변화 | 광택 나일론 → 무광(wind 5/8), 금줄 → 투톤 | "주름 정리" 허용 | 미해결 |
| 없던 글자 · 로고 · 캡션 | 시계 다이얼 "JAPAN…", 소매 로고, "MAESTRO 95" 자막, 자전거 사진 아래 "MERIDA · GIANT" 캡션 | 업스케일 + 글자 단서 | 없던 글자 검사로 막다가 10-11 에 글자 판단 자체를 뺌 |
| 가려진 곳 · 안 보이는 면 지어냄 | 손에 가린 깔창 로고, 엔진룸 사진에 운전석, 위에서 찍은 의자에 다리, 폰 뒷면 사진에 켜진 앞면 | 한 장으로 구도를 바꾸게 함 | "한 장 + 구도 변경"은 실패로 결론 → 여러 각도 업로드 (10-01 §4) |
| 다른 물건이 생김 | 신발 사진에 재킷 · 셔츠 | 잠금 문장의 종류별 예시(옷은 펼치고…)를 연출 지시로 읽음 | 예시 문장 삭제 (10-01 §2) |
| 개수 · 복제 | CD 2 → 1 · 3장, 레고 설명서 2 → 3, 캘린더 카드 1 → 3, IU 로고 두 번, PS5 케이스 복제 | 생성은 개수를 못 지킨다. 비슷한 조각이 많을수록 심함 | 여러 개는 본체 하나만 대표 (10-11 §1), 개수 게이트(eval) |
| 모양 · 부품 변화 | 자전거 드롭 핸들로, 레고 집게 날 분리, 후드가 셔츠 깃으로 | 선 그림 · 흔한 모양으로 끌림 | **검사 없음** — 다음 과제 |

**틀렸던 판단**: 400px 데이터셋으로 "생성이 물건을 바꾼다"고 결론 → 폰 사진(750px+)에선 대부분 뒤집힘. 입력 화질이 원인의 큰 부분이었다 (09-27 §8-3).

## 2. 프롬프트 — 넣을수록 나빠졌다

| 시도 | 결과 | 노트 |
|---|---|---|
| 지킬 것 목록 강조 (tags, logos, stain…) + negative_prompt | 목록의 단어를 그림 — 흔한 코트 · 태그 | 10-09 §3 |
| 금지하려고 쓴 단어 ("no text", "CD case", "shrink wrap", 뺄 물건 이름) | 쓰면 그리거나 지운다 — LP 를 CD 케이스로, 고른 CD 케이스까지 벗김 | 10-03 §11-7 · §12 |
| 물건 이름 ("coat") | 흔한 모양으로 — 숄 후드가 평범한 후드. 이름 빼니 원래 후드 | 10-08 §4 |
| 틀을 세게 (80% 채우기 · 정면 반듯이 · 대칭) | 사진이 안 맞으면 물건을 바꿔서 맞춤 | 10-03 §12 |
| 프리셋 + 선 그림 + 구도 + 꼬리를 이어 붙인 긴 문장 | 서로 부딪힘 ("주름 펴기" vs "모양 그대로") | 10-08 §6 |
| 정답 구도를 정답 물건 기준으로 묘사 (단추 · 옷깃) | 후드 코트에 없는 옷깃 · 단추 | 10-08 §7 |
| 재시도 문장에 검사 목록 표기 그대로 | `[presence only]` 글자가 이미지에 그려짐 | 10-09 §3 |
| 세트에 최소 문장 "the item" | 피규어 하나만 그림 | 10-09 §3-2 |

**이긴 것**: 최소 문장(메인 사진 + 선 그림 + 동작 한 줄) — 한 개짜리 물건 2/2 1차 통과 (10-09 §3-1 · §3-2).

## 3. 참고 이미지 — 사진을 넣으면 베낀다

| 시도 | 결과 | 노트 |
|---|---|---|
| 정답 **원본 사진**을 생성에 | 아이폰 → 정답의 16, 코트 → 정답 티셔츠, 맥북 몸체가 에어로. **게이트는 통과** | 10-04 §16 ③, 10-05 §12 ①, 10-08 §2 (같은 실수 3번) |
| 선 그림 (정답 윤곽) | 몸체 유지 — 채택. 그러나 선 그림 속 피규어 · 다른 차량까지 그림, 두 면 정답이면 없는 앞면 지어냄 | 10-05 §12 ②, 10-09 §3-2 |
| 판매자 다른 각도 + 선 그림 4장 | 다른 각도를 선화 그림체로 옆에 콜라주 (옷) | 10-08 §4 |
| 고주파 섞기 (원본 디테일을 결과에) | 하자가 아니라 원본 방의 반사가 돌아옴, 정렬 불가 | 09-27 §8-1 |

## 5. 검사(게이트)가 놓치거나 틀린 것

**놓친 것 — 검사를 못 했는데 통과로 처리**
- detect 실패 → 앵커 0 → 게이트 생략 → 그냥 나감 (09-26 §5-1)
- judge 캐시가 옛 점수를 돌려줌 (09-26 §5-2)
- 개수 게이트 504 → "막지 않음"으로 통과 (10-10 §8-1)
- 검사할 마크 0개 → 검사 없이 통과, 에어팟 모양 바뀜 (10-11 §10)
- Gemini 한도(429) → 조용히 전부 배경 교체 (09-29 §5-1)

**구조적으로 못 보는 것**
- verify 는 "있어야 할 게 있나"만 — 생긴 것 · 사라진 것 · 개수 · 모양을 못 봄 (09-27 §5, 10-01 §1-4)
- 원본 정답 사진을 베낀 결과도 통과 (10-08 §2)
- 세트는 배치를 바꾸라 했는데 게이트는 원본 **위치** 기준으로 "사라짐" (10-10 §3)

**오탐 — 검사기 오차가 생성기보다 컸던 때**
- OCR 글자 가드: "17어"↔"17에", "00 3060" 쪼개 읽기, "H.M"↔"H-M" — 반려 대부분이 읽기 흔들림 (09-27 §9-1) → OCR 가드 삭제
- 없던 글자 게이트: 설명서 "1" · "2" 표시, 폰 상태 표시줄 (10-09, 10-10)
- 작은 마크(Syncros · ULTEGRA): 같은 결과를 한 번은 사라짐, 한 번은 보존 (10-11 §10)
- 합친 검사(VERIFY_COMBINED)는 더 엄격하지만 빠르지 않음 — 기본 꺼짐 (10-05 §11)

**점수 지표**
- judge 는 사람 실패 판정과 11/17 만 일치, 점수가 3~4 에 몰림 → 운영에서 제거 (10-05 §3)
- item_dino: "바뀜" 중앙 0.918 vs "그대로" 0.958 — 범위가 겹쳐 못 가름 (10-04 §3)
- 정렬 신호(SIFT): 인라이어 낮은 8건 중 절반이 멀쩡 (09-27 §8-2)
- 외부 자료도 같은 결론: 유사도 · VLM 점수는 사람과 Pearson 0.4 수준, 보증 불가 (10-11 §9)

## 6. 분석 · 분류가 흔들린 것

- 같은 사진의 각도가 같이 넣은 사진에 따라 바뀜 (temperature 0 인데도) (10-04 §12)
- wear_level: 정답 none 을 light 로 과민 7/14 · 11장, 디자인 · 하자 구분 불가 → 질문 자체를 바꿈 (10-01, 10-04 §4)
- 시계 다이얼 잔글씨를 simple 로 → 생성 → 다이얼 다시 그림 (09-29 §5-1)
- 교재를 "toy package", 못 읽는 걸 짐작 ("LP 바이닐", "사카이 스타일") (10-04 §12)
- 책 · CD 를 document 로 → 무조건 배경 교체. 처음 고친 방향(문서도 글자 양으로)도 틀림 (10-03 §9)
- 글자 읽기 응답 끝에 엉뚱한 토큰 → JSON 깨짐 → 조용히 "글자 없음" (10-01 §6-3)
- 캘린더 구성품 5개로 셈 (실제 7종), 504 직후 응답 (10-10 §3)
- 세트 경로가 거의 안 켜짐 — 분석이 세트로 안 묶음 (10-10 §1)

## 7. 버린 설계 방향

| 방향 | 버린 이유 | 노트 |
|---|---|---|
| 하자를 목록(앵커)으로 지키기 | 이름 붙일 수 있는 것만 지키고, 목록이 하자를 그리게 함 | 09-27 §6 |
| 한 장으로 구도 바꾸기 | 안 보이는 면을 지어낼 수밖에 없음 | 10-01 §4 |
| 규칙 각도 · 필수 면 (`coverage.REQUIRED`, 예시 구도) | 각도 단어로 줄이면 가림 · 일부만 찍힘이 사라지고 물건마다 목록이 필요 → VLM 사진 검토로 (10-09 §7), 코드 삭제 10-11 | 10-04 §15, 10-11 §11 |
| 준비물 정해진 목록으로 맞추기 | "모든 물건 이름을 미리 정해 놔야" → VLM 대조로 | 10-05 §14 |
| 판매자에게 상태 고르게 하기 | 모델이 판단해야 의미가 있다 (사용자) | 10-04 §4 |
| 여러 구성품을 한 장에 배치 생성 | 비슷한 조각은 복제 · 지어내기 → 대표는 본체 하나 | 10-10 §9, 10-11 §1 |
| 배경 교체 자동 강제 | 판매자가 고르게, 위험 이유만 안내 | 10-11 §2 |
| 실패 확률 퍼센트 표시 | 강제 교체했던 이유들은 실측이 없다 → 보류 | 10-11 §2 |
| 예뻐 보이는 배치 실험 (10-08~10-10) | "정직한 사진"에서 멀어짐 — 원칙 다시 세움 | 10-10 §9 |

## 아직 열린 실패 (다음 과제)

1. **모양 · 없던 부분 · 복제를 보는 검사가 없다** — 핸들 · 폰 앞면 · 이어컵 · 케이스 복제. 원본에서 질문을 만드는 쪼갠 검사 (`honesty-metric/11-carret-design.md`)
2. 검사를 못 하면(504 · 마크 0개) 통과로 처리되는 곳이 남아 있다
3. 정직함 보증 숫자 없음 — 사람 정답 세트로 틀린 통과율 상한을 재야 한다 (5% 보증에 품목별 60~120장)
4. 소재 · 색 변화, 작은 하자 지워짐 — 생성 전엔 모름
