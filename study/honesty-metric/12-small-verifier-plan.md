# 작은 판별 모델 — 원본 · 결과 쌍이 "다른가" (계획, 10-13 시작)

결정 기록: `study/2026-10-12-parts-seedream-jobs.md` §6 · §16. 설계 배경: `11-carret-design.md` (정의 · 보증).

## 1. 왜

10-12 실패는 거의 **생김새가 원본과 달라졌는데 VLM 게이트가 말로는 못 잡는** 유형이었다.

| 사례 | 유형 | 게이트 |
|---|---|---|
| 하이브리드 자전거 (flux) | 일자 핸들 → 드롭, 서스펜션 포크 → 일자 | 통과 (로고만 봄) |
| 헤드폰 (flux, p04 실행) | 버튼 2~3개 추가 | 검사 안 함 (마크 0개) |
| 코트 (Seedream) | 없던 단추줄 · 후드 모양 변형 | 검사 안 함 |
| 폴드 (Seedream, 정답 iphone) | 넣은 사진에 없는 뒷면 · 카메라 | 검사 안 함 |

VLM 검사는 느리고(5~10초, 생각 포함) 실행마다 흔들린다. 쌍을 직접 비교하는 작은 모델은 빠르고(로컬) 같은 입력에 같은 답 →
보증 숫자(10 · 11)에 재현성이 생긴다.

## 2. 무엇을 맞히나

- 입력: 원본 사진(들) + 생성 결과 1장
- 출력: `p(다름)` (사진 단위 이진, 11 §1 정의 그대로) + 가능하면 **어디가** (패치 지도 → 칠한 곳 고치기와 이어짐)
- 처음엔 이진만. 추가 · 누락 · 변형 구분은 라벨이 쌓인 뒤

## 3. 데이터 — 지금 있는 것 (10-12 기준)

| 무엇 | 수 | 위치 |
|---|---|---|
| 생성본 inspect (원본 · 결과 쌍) | 95 (게이트 통과 75 · 검사 안 함 20) | `eval/results/runs/*/storage/quality/*_inspect.json` |
| 생성 시도 이미지 (탈락 포함) | 146 | `runs/*/storage/attempts/` |
| 사람 정직함 라벨 | **4** | `eval/data/honesty_labels.json` |
| 10-12 결과 (Seedream 11 + flux) | 약 20 | `seedream-*`, `coat-fixed-1012`, `phones-fixed-1012`, `picks-gen-1012` |

**막히는 곳은 라벨**. 학습 · 평가에 최소 200~300쌍, "다름" 이 충분히 섞여야 한다.

라벨을 늘리는 길 (싼 것부터):

1. **사람 라벨** — 라벨 페이지(`eval/label_honesty.py`, 8002)로 95쌍 + 10-12 20장. 판정은 8001 의 인풋 칸을 다 보고
   (메모리: 판정 전에 인풋 다 보기). 라벨 기준 먼저 정하기 (§6)
2. **만든 "다름"** — 원본을 일부러 바꾼 쌍: 패치 지우기(인페인팅으로 부품 지움), 다른 게시글 부품 붙이기,
   좌우 · 색 바꾸기, 다른 생성 시도로 바꿔치기. 라벨이 공짜, 단 실제 실패와 분포가 다르다 → 평가는 사람 라벨로만
3. **판매자 칠하기** — `inpaint_rounds` 의 칠한 곳 = "다른 곳" 후보 (11 §2: 후보이지 정답은 아님)

## 4. 모델 — 처음부터 학습하지 않는다

이미 로컬에서 도는 **DINOv2 (embedder.py, 384차원, 패치 14px)** 를 얼린 채 특징만 뽑고, 위에 작은 머리만 학습. CPU 로 된다.

| 단계 | 특징 | 머리 |
|---|---|---|
| v0 (기준선) | 지금 있는 숫자: `visual_similarity` · `item_similarity` · `item_patch_similarity` | 임계값 1개 / 로지스틱 |
| v1 | 원본 패치 ↔ 결과 패치 **상호 최근접 매칭** 분포 (자리 고정 X — 생성은 자세가 바뀐다) — 매칭 안 되는 패치 비율 · 하위 백분위 · 히스토그램 | 로지스틱 / 작은 MLP |
| v2 | 원본 여러 장 합친 패치 집합 vs 결과 (헤드폰 p04 처럼 다른 각도에만 있는 부품) | 같음 |

주의: `patch_similarity` 는 **같은 자리 3×3** 비교라 배경 교체(같은 배치)용이다. 생성본은 자세 · 크기가 바뀌어
자리 비교가 깨진다 → v1 의 매칭 방식이 핵심.

## 5. 평가 — 보증과 같은 방식

- 나누기: **게시글 단위** (같은 물건이 학습 · 평가에 같이 들어가지 않게)
- 숫자: 사람 라벨에서 놓침률(다른데 통과) · 오탐률. 지금 VLM 게이트와 **같은 라벨 세트로** 비교 → 포트폴리오 결론
  ("API 검사 vs 로컬 측정 검사")
- 보증: 통과 기준을 고를 때 10 의 신뢰 상한 (통과 59장에 다름 0 → 5%)

## 6. 10-13 시작 순서

1. **라벨 기준 정하기** (사용자와) — 10-12 §1 남은 일:
   - 누락은 판매 대상만? (셔츠 택처럼 규칙대로 뺀 건 같음)
   - 뭉개진 글자는 변형?
   - 검사 안 한 사진(gate None)은 통과와 따로
2. **라벨 대상 목록** 만들기 — 95 inspect + 10-12 결과 → `label_honesty.py --all` 로 띄우기 (무료)
3. **v0 기준선** — 라벨 단 만큼 지금 숫자 3개로 놓침 · 오탐 표 (무료, 몇 줄)
4. **v1 특징 뽑기 스크립트** — `eval/pair_features.py` (가칭): 원본 · 결과 → 매칭 분포 특징, 캐시 (무료, CPU)
5. **만든 "다름"** 20~50쌍으로 v1 이 신호를 내는지부터 (학습 전에 분리가 되는가)

유료 호출 없음 (전부 저장된 이미지 + 로컬 DINO). 만든 "다름" 에 인페인팅을 쓰면 그때만 허락.

## 7. 위험

- 라벨이 적으면 머리가 외운다 → v0 · v1 을 단순하게, 게시글 단위 나누기
- 만든 "다름" 만 잘 맞히고 실제 실패를 놓칠 수 있다 → 평가는 사람 라벨만
- 배경 · 조명이 바뀐 것까지 "다름" 으로 볼 위험 → 물건 영역만 (누끼 `compositor.isolate` 재사용)
