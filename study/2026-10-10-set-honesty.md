## 3. 캘린더는 왜 안 됐나

넣은 사진 3장 + 1 · 2차 결과를 나란히 보고 판단 (직접 확인).

- 생성이 틀린 것: 큰 판에 "IU" 가 위아래 두 번 (로고 복제), 포토카드 · 액자를 지어냄
- 구성품 목록이 틀렸다: 분석은 5개, 상자 인쇄 목록은 *달력 · 다이어리 · 포토카드 · 탁상 액자 · 엽서 세트 · 포스터 · 스티커* 7종.
  분석 호출이 504 로 한 번 실패한 뒤의 답
- 기준 사진이 잘려 있다 (`cut_off` 로 원래 생성 안 하던 이유)
- 게이트가 세트에 안 맞다: "사라짐 'IU'(왼쪽 위)" 는 원본 **위치** 기준인데, 세트는 배치를 바꾸라고 시킨 것이라 위치가 바뀌는 게 정상

레고는 조각이 서로 다르게 생겼고(본체 · 사람 · 책자) 캘린더는 흰 인쇄물 여러 개에 같은 로고 · 수채 무늬다.
생성 모델은 비슷한 것 여러 개를 그리면 개수와 "어느 게 어느 것"을 헷갈린다.

## 4. Langfuse 에 실험 기록이 안 가던 이유

사용자: "이거 왜 랭퓨즈에 아무것도 안가냐".

`run_posts.py` 가 `LANGFUSE_PUBLIC_KEY=""` 로 키를 지웠다 (커밋 `a955ae0`). 목적은 Langfuse 에 등록된 옛 프롬프트가
저장소 프롬프트를 덮지 않게 하는 것이었는데 트레이스까지 꺼졌다.

- `settings.langfuse_prompts` (`LANGFUSE_PROMPTS=false`) — 프롬프트 조회만 끄고 트레이스는 그대로 (`app/core/prompt_registry.py`)
- `run_posts.py` 는 키 대신 이 값을 끈다. 다음 실행에서 `objects` · `transform` 트레이스가 들어간 것을 API 로 확인

## 8. 캘린더 다시 — 정답 (`goods-ref-1010`) · 분리 문장 (`goods-sep-1010`)

조건: `--set-prompt --force-generate --ref-text --ref-sketch`, flash, 각 약 $0.04 (허락 받음).

### 8-1. 정답만 (`goods-ref-1010`)

배치 문장(모델이 정한 것) 번역: "본체를 왼쪽 위에 눕히고 그 옆에 다이어리와 스티커 시트를" — **문장이 중간에 잘렸다.**
`layout_plan` 이 `prompt_safe` 를 거치며 글자 잠금 길이(`TEXT_LOCK_MAX_CHARS`)로 잘림 → `prompt_safe(text, limit)` 로 400자.

결과: 1차 통과 · 채택 (219초). 두 줄 펼침으로 깔끔하지만 스티커(얼굴 9컷 → 얼굴 3 + 동그란 스티커 6)를 지어내고,
빨간 옷 카드 복제, 스프링 달력 빠짐. **개수 게이트는 504 로 못 돌았는데 "막지 않음"으로 통과.**

### 8-2. 분리 문장 (`goods-sep-1010`)

사용자: "상자와 구성품들을 하나하나 분리해서 한 화면에 보이게". `set_layout`:
"Take the box and every piece apart and lay them out separately, side by side, so each one is fully visible in one frame."
(상자와 모든 구성품을 하나씩 떼어 따로 나란히 놓아, 한 화면에 각각 다 보이게.)

| 시도 | 구도 | 정직 |
|---|---|---|
| 1차 | 원한 대로 — 상자 · 스프링 달력 · 받침 · 스티커 9컷 · 빨간 옷 카드 모두 따로 | 모자 쓴 카드 1장 → 3장 |
| 2차 | 더 단정 | 원본에 없는 은색 금속 액자, 스프링 달력 빠짐 |

두 번 다 개수 게이트 탈락 → 배경 교체. 1차는 거의 맞았는데 "본체 0 · 포스터 0" — 분석 이름("main piece", "photo pack")이 모호하고
목록이 틀려 엉뚱한 기준으로 셌다. 반대로 카드 복제 같은 진짜 문제는 이 기준으로 못 잡는다.

- 정답별 구도 문장은 **구도를 확실히 바꾼다**
- 생긴 게 비슷한 조각이 많은 세트는 생성이 복제 · 지어내기를 한다 — 사용자: "이건 안 되네 ㄹㅇ", "한 화면에 여러 가지 같이 주는 건 안 되나 보다"

## 9. 정직한 사진인가, 예쁜 사진인가 — 방향 다시 잡기

사용자: "내가 하려는 건 정직한 사진 생성인데 너무 미적으로 가고 있나".

**그렇다.** 10-08 ~ 10-10 실험(정답 구도 · 선 그림 · 배치 문장 · 세트 JSON 배치)은 거의 *더 보기 좋게 놓기*였고,
게이트는 그 뒤에서 오탐을 고치는 역할이었다. 정직함으로 다시 매기면:

| 결과 | 보기 | 정직 |
|---|---|---|
| 레고 2차 (10-09) | 좋음 | 설명서 2 → 3 (없는 물건) |
| 레고 (10-09) | 좋음 | 집게 날이 본체에서 떨어짐 (파손으로 오해) |
| 캘린더 4번 (오늘) | 좋음 ~ 보통 | 로고 · 카드 복제, 스티커 · 액자 지어냄 |
| 배경 교체 | 덜 예쁨 | 거짓 없음 |

어디까지 되나 — 한 장에 여러 개:

| | 레고 (됨) | 캘린더 (안 됨) |
|---|---|---|
| 조각 생김새 | 서로 확연히 다름 | 거의 같음 (흰 종이 · 같은 로고) |
| 조각 수 | 6개 3종류 | 7종 이상 |
| 원본 | 다 보임 | 겹침 · 잘림 |

### 9-1. 이후 방향

원칙: **"원본에 있는 것만, 있는 그대로"를 먼저, 예쁨은 그다음.** 생성이 할 일은 배경 · 조명 · 기울기 정리.
배치를 새로 짜는 건 조각이 뚜렷하고 적을 때만.

1. **게이트를 정직함 기준으로** (가장 먼저)
   - 검사를 못 하면(504) 통과가 아니라 다시 검사 → 그래도 못 하면 배경 교체
   - 개수 게이트의 기준 목록을 정확하게 — 모호한 "main piece" 대신 실제 이름, 상자 인쇄 목록과 대조
   - 세트는 글자 "위치"가 아니라 "있나 · 몇 번"만 본다 (위치는 배치를 바꾸면 당연히 바뀐다)
   - 복제 검사: 같은 카드 · 로고가 원본보다 많아졌나
2. **세트는 대표 1장 + 구성품 상세로 나누기**
   - 대표 사진: 본체 하나만 생성 (한 물건은 잘 지킨다 — 10-09 최소 프롬프트)
   - 구성품: 판매자 사진 배경 교체를 상세 사진 칸에. 게시글은 원래 여러 장 — 한 장에 다 몰 필요 없다
   - 레고처럼 조각이 뚜렷하고 6개 안팎이면 지금처럼 한 장 세트 생성도 선택지로 남긴다
3. **생성 대상을 좁힌다**: 비슷한 조각이 많은 세트(굿즈 · 카드 · 인쇄물)는 생성 안 함 — 배경 교체 + "펼쳐서 다시 찍기"
4. **평가 숫자를 정직함으로**: 개수 변화 · 로고/글자 변화 · 모양 변화(분리 · 파손처럼 보임) · 하자 지워짐. 예쁨(judge)은 맨 뒤
5. 정답 구도는 각도 · 여백 위주로. 구성품 자리를 정하는 `set_layout` 은 2번의 "한 장 세트"에서만
